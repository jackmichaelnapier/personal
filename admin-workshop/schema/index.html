Station 03 · The Drafting Table

Write data, not vibes.

If you can't describe the output as a data shape, you can't tell whether a run was successful. The schema is what makes the skill auditable, composable, and re-runnable.

"A reconciliation" is a vibe. match_status, discrepancies[], recommendation is a shape.
🦆
Otto thinks…

The chemistry analogy: a reaction has reactants, conditions, products, with stereochemistry, yield, byproducts. A skill is the same. Every field has a type, every output has a shape. If you can't draw it on the back of an envelope, you can't compose it.

Vibe vs shape.

Vibe

input: an invoice
output: a reconciliation

Looks fine alone. Breaks the moment a downstream skill needs to consume it. No types, no fields, no audit trail.

Shape

{ supplier, line_items[], total, currency }
{ match_status, discrepancies[], recommendation }

A downstream payment-execution skill can consume this directly. Every field has a type. The skill is auditable run-by-run.

Try this

Turn this vibe into a schema.

Rewrite the I/O for supplier-invoice-reconciler.

starting point (too vague) 
name: supplier-invoice-reconciler
input:  an invoice
output: a reconciliation
there are many right answers; this is one.
one strong version 
name: supplier-invoice-reconciler

input:
  invoice:
    supplier: string
    invoice_number: string
    issue_date: date
    currency: string
    line_items: [{sku, qty, unit_price, line_total}]
    invoice_total: float
  matching_po:
    po_number: string
    line_items: [{sku, qty_ordered, agreed_unit_price}]
  grn:                          # goods-received note
    received: [{sku, qty_received, condition: 'ok'|'damaged'|'short'}]

output:
  match_status: 'clean' | 'minor_discrepancies' | 'major_discrepancies'
  discrepancies:
    - type: 'qty' | 'price' | 'extra_line' | 'missing_line' | 'damaged'
      sku: string
      expected: any
      actual: any
      eur_impact: float
  recommendation: 'pay_in_full' | 'pay_partial' | 'hold_for_supplier_response' | 'reject'
  reasoning: string             # 1-2 sentences
  next_action: string           # who needs to do what, by when

Notice what the schema buys you. eur_impact per discrepancy surfaces the 2%-overcharge-on-80-SKUs leak that gut-feel misses. The explicit recommendation removes the "let me think about it" delay that kills follow-up. And the downstream bank-payment-executor skill knows exactly what to consume.

Before you scroll on

Pick a real document. Write its schema.

Grab the last supplier invoice you reconciled. Write down the schema you'd want — every field with a type. Five minutes. You'll discover at least one field your skill needs that you'd have forgotten.
